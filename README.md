# PetSpeak — Cat Vocalization Context Classifier

PetSpeak is a student-level machine-learning project that classifies a cat vocalization into one of three **recording contexts**:

- `waiting_for_food`
- `isolation`
- `brushing`

The project uses classical audio signal processing and supervised machine learning. It does **not** claim to translate cat language. After the classifier predicts a probable context, a separate rule-based module selects a playful English sentence from a predefined list.

> **Scientific disclaimer:** This is an experimental behavioral-context prediction, not a literal translation of animal language.

## 1. Project objective

The complete workflow is:

1. Scan a local copy of the public CatMeows dataset.
2. Build an editable metadata CSV containing the audio path, class, and cat identifier.
3. Load each recording safely and convert it to a shared 16 kHz, mono, normalized, three-second representation.
4. Extract a fixed-length MFCC-centered feature vector.
5. Split the dataset by cat identity, never by individual audio file.
6. Tune and compare a Random Forest and an RBF SVM with grouped cross-validation.
7. Evaluate both models on cats that were not used during training.
8. Save the selected estimator, configuration, metrics, plots, and split manifest.
9. Run predictions from the command line or the offline Streamlit interface.

## 2. Scientific limitations

PetSpeak predicts which of the three CatMeows experimental contexts is acoustically most probable. It does not decode intentions, emotions, words, or a universal animal language.

Important limitations include:

- CatMeows is small: the published dataset contains 440 recordings from 21 cats.
- It contains only three controlled contexts and two breeds.
- Recording devices, rooms, owners, and individual cats can introduce acoustic shortcuts.
- A high probability is model confidence within this limited task, not certainty about the animal's internal state.
- A silent, noisy, clipped, or out-of-distribution recording may still produce a prediction, but that prediction may not be meaningful.
- The playful sentence is selected from a predefined rule-based list. It is not generated by the classifier and is not a literal translation.

## 3. Why the split is grouped by cat

A random split by audio file would allow recordings from the same cat to appear in both training and test sets. A model could then learn the individual cat's voice, microphone conditions, household acoustics, or recording routine instead of learning patterns associated with the context.

PetSpeak therefore uses the cat identifier as a **group**:

- `GroupShuffleSplit` proposes train/test divisions containing non-overlapping cats.
- The project chooses a reproducible split that contains all three classes in both parts and has a reasonable class balance.
- Hyperparameter selection is performed only on the training cats with `StratifiedGroupKFold` when feasible.
- The held-out test cats are not used to choose the model or its hyperparameters.

`RANDOM_STATE = 42` is used wherever randomness is relevant.

## 4. Dataset preparation

Download the public **CatMeows** dataset from its official Zenodo record:

- https://zenodo.org/records/4008297

The official WAV filenames follow this convention:

```text
C_NNNNN_BB_SS_OOOOO_RXX.wav
```

Where:

- `C` is the context: `B` = brushing, `F` = waiting for food, `I` = isolation;
- `NNNNN` is the cat's unique identifier;
- `BB` is the breed;
- `SS` is sex/neuter status;
- `OOOOO` is the owner's identifier;
- `R` and `XX` identify the recording session and vocalization.

Extract the dataset audio files anywhere below:

```text
data/raw/
```

For example, either of these layouts is acceptable:

```text
data/raw/F_CAT01_EU_FN_OWN01_101.wav
```

```text
data/raw/waiting_for_food/cat_01/example.wav
```

The metadata builder supports `.wav`, `.mp3`, `.ogg`, `.flac`, and `.m4a` when the required local decoder is available. WAV and FLAC are the most portable formats.

### Conservative label detection

`src/config.py` contains the editable `LABEL_ALIASES` dictionary. The builder checks:

1. the official CatMeows pattern;
2. parent folder names;
3. filename tokens;
4. explicit tokens such as `cat_12`, `subject-04`, or `animal03`.

It does not silently guess when a class is missing or conflicting. Every discovered file is written to `data/metadata.csv`; unresolved rows receive `status=manual_review` and empty fields that can be corrected manually.

After editing the CSV, training accepts rows whose:

- `label` is one of the three canonical classes;
- `cat_id` is non-empty;
- `audio_path` is non-empty.

## 6. Installation

Use Python 3.11.

Create a virtual environment:

```bash
python -m venv .venv
```

Activate it on Windows Command Prompt:

```bat
.venv\Scripts\activate
```

Activate it on Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Activate it on macOS or Linux:

```bash
source .venv/bin/activate
```

Upgrade pip and install the dependencies:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### Optional decoder support

`librosa` and `soundfile` read WAV, FLAC, and many OGG files directly. MP3 and especially M4A support can depend on the operating system and installed audio backends. Install FFmpeg if one of those formats cannot be decoded.

Verify FFmpeg with:

```bash
ffmpeg -version
```

The project logs and skips an unreadable training file instead of stopping the entire feature extraction process.

## 7. Build metadata

Place the extracted recordings under `data/raw/`, then run:

```bash
python -m src.build_metadata
```

Custom input and output paths are also supported:

```bash
python -m src.build_metadata --raw-dir path/to/audio --output data/metadata.csv
```

Open `data/metadata.csv` and review rows marked `manual_review`. Correct `label` and `cat_id` directly in the CSV when necessary.

Expected columns are:

```text
audio_path,label,cat_id,status,notes
```

## 8. Audio preprocessing and features

All training, evaluation, CLI prediction, and Streamlit prediction use the same functions in:

```text
src/audio_processing.py
src/feature_extraction.py
```

Each recording is:

1. decoded safely;
2. converted to mono;
3. resampled to 16,000 Hz;
4. cleaned of NaN and infinite values;
5. peak-normalized;
6. trimmed at the leading and trailing edges with `top_db=35`;
7. center-padded or center-cropped to exactly three seconds.

The fixed feature vector contains mean and standard deviation statistics for:

- 20 MFCC coefficients;
- delta MFCC;
- delta-delta MFCC;
- zero-crossing rate;
- spectral centroid;
- spectral bandwidth;
- spectral rolloff;
- RMS energy;
- 12-bin chroma.

The resulting vector has 154 values per recording.

Features are cached in:

```text
data/processed/features.npz
```

The cache fingerprint includes metadata rows, file sizes, modification times, preprocessing settings, feature settings, and class names. It is rebuilt automatically when these inputs change.

Force a rebuild with:

```bash
python -m src.train --force-features
```

## 9. Train and compare models

Run:

```bash
python -m src.train
```

The script trains and tunes:

- Random Forest with balanced class weights;
- StandardScaler + RBF SVM with balanced class weights and probability estimation.

Hyperparameters are chosen using grouped cross-validation on training cats only. The selected model is the one with the highest grouped cross-validation macro F1-score. Test performance is reported only after tuning and is not used for selection.

The final console summary includes:

- valid audio-file count;
- distinct cat count;
- class distribution;
- train/test recording counts;
- cats in each split;
- grouped CV and held-out performance for both models;
- selected model;
- saved output paths.

## 10. Run evaluation again

Training already creates all evaluation reports. To reload the saved model and regenerate the selected model's held-out reports from the saved split manifest, run:

```bash
python -m src.evaluate
```

The evaluation includes:

- accuracy;
- balanced accuracy;
- macro precision;
- macro recall;
- macro F1;
- weighted F1;
- classification report;
- confusion matrix;
- per-class precision, recall, F1, and support.

## 12. Launch Streamlit

Run:

```bash
streamlit run app.py
```

The interface provides:

- common audio-file upload;
- audio playback;
- original duration, sample rate, and channel count;
- the exact preprocessed waveform;
- a mel spectrogram;
- predicted context and confidence;
- probabilities for all three classes;
- a rule-based playful interpretation;
- scientific disclaimers and graceful error messages.

The model is loaded once with `@st.cache_resource`, while uploaded-audio preprocessing and feature extraction are cached with `@st.cache_data`.

## 13. Run tests

The tests generate synthetic audio arrays and do not require CatMeows.

```bash
pytest
```

They verify:

- padding of short audio;
- center-cropping of long audio;
- normalization;
- safe silent-audio handling;
- fixed-length, finite feature vectors;
- translations for every class;
- deterministic sentence selection;
- rejection of unknown classes.

## 14. Common errors and solutions

### `Metadata file not found`

Run:

```bash
python -m src.build_metadata
```

### `No valid metadata rows remain`

Open `data/metadata.csv`. Ensure that every usable row has:

- a valid `audio_path`;
- a canonical `label`;
- a non-empty `cat_id`.

Unknown or conflicting labels are intentionally not guessed.

### `Could not create a grouped train/test split containing all classes`

The corrected metadata does not provide enough cat-level class coverage. Check that:

- cat IDs are correct and consistent;
- the same cat is not written under several IDs;
- each context has recordings from enough distinct cats;
- all three labels use their exact canonical spelling.

### `Could not decode ...`

The file may be corrupted or its codec may not be supported locally. Try converting it to PCM WAV or installing FFmpeg. During training, the file is logged and skipped; prediction of a single invalid file exits with a clear error.

### Streamlit says the model has not been trained

Run, in order:

```bash
python -m src.build_metadata
python -m src.train
streamlit run app.py
```

### `ModuleNotFoundError: No module named 'src'`

Run commands from the `PetSpeak/` project root, not from inside `src/`.

### PowerShell blocks virtual-environment activation

For the current PowerShell process, a common solution is:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
```

### The feature cache appears outdated

Delete it or run:

```bash
python -m src.train --force-features
```

## 15. Possible future improvements

Reasonable next steps include:

- collecting more cats, breeds, devices, and environments;
- adding an explicit unknown/out-of-distribution rejection mechanism;
- measuring calibration quality in addition to classification metrics;
- using repeated grouped validation for more stable uncertainty estimates;
- comparing additional interpretable classical models;
- adding noise augmentation only inside training folds;
- analyzing which acoustic features drive each prediction;
- deploying the same preprocessing logic to an embedded or mobile prototype;
- testing whether performance transfers to recordings made outside the original dataset.

A deep-learning model should only be added when there is enough data and a clear experimental reason. It is intentionally excluded from this first version.
